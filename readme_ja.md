## ✨ 概要

**NyaLauncher** は **Avalonia UI 12.1.1** と **.NET 10** を用いて構築されたクロスプラットフォームの Minecraft ランチャーです。<br>
軽量で高速なだけでなく、**プライバシー保護** と **プラグイン拡張性** に重点を置き、ゲームを楽しみながら完全なコントロールを提供します。

---

## 🎯 主な特徴

- 🚀 **クロスプラットフォーム対応** — Windows、macOS、Linux をサポートし、ほぼ同一の見た目を提供。
- 🔌 **拡張可能なプラグインフレームワーク** — 組み込み機能とサードパーティ製コンポーネントは共通契約を使用し、パッケージ検出、権限確認、ライフサイクル、設定、Minecraft インスタンス拡張まで統合済み。
- 🛡️ **プライバシーファースト** — テレメトリや第三者トラッキングなし。レジストリ等からのトークン漏洩を抑える独自のトークン暗号化技術を使用。
- ⚡ **軽量かつ高効率** — .NET 10 と Avalonia を基盤に責務を明確に分け、必要な機能だけを拡張可能。
- 🎨 **モダンなUI** — Avalonia ベースの滑らかなデザインとカスタマイズ対応。
- ✊ **完全オリジナル** — 他のランチャーのコードを流用せず、模倣もしない方針。

## ⬡ ポリゴンコンポーネントフレームワーク

- `NyaLauncher.Plugin.Abstractions` は Avalonia に依存しない公開契約を提供し、サードパーティ拡張はランチャーの UI 実装を参照せずにコンポーネントを記述できます。
- `[0,1]` の正規化座標で凸多角形・凹多角形の輪郭を宣言し、推奨・最小・最大サイズを個別に指定できます。
- コンポーネントはテキスト、切り抜き対応画像、ボタン、プログレスバー、ドロップダウンメニューを組み合わせられ、ボタンとメニュー項目は安定したアクション ID で非同期コマンドを呼び出します。
- 対話可能な各コンポーネントはファクトリーから独立したランタイムインスタンスを受け取り、増加する `Revision` を持つ不変スナップショットでテキスト、画像ソース、進捗、メニュー項目、有効、表示、不確定状態を更新します。
- 登録前に ID、形状、サイズ、要素、アクション参照、進捗範囲を検証し、拡張側は安定したエラーコードで問題を特定できます。
- ホストは実際の多角形輪郭でクリップとヒットテストを行うため、透明な角がホバーやクリックを奪うことはありません。
- ポリゴンコンポーネントと従来のボタンコンポーネントは同じコンポーネントカタログに入り、ワークスペースのドラッグ＆ドロップ、相対配置、拡大縮小、重なり順、サイドバーを再利用します。
- gp3 には「アカウント選択」「ゲームインスタンス選択」「バージョン選択と管理」「ゲーム起動」「スキンとマント」「ダウンロードタスク進捗」が組み込まれています。既存のインスタンスコンポーネントはクイックドロップダウンを維持し、新しいバージョンコンポーネントから完全な管理ページを開けます。
- `workspace.json` には安定したコンポーネント ID、機能エリア、相対座標、重なり順のみを保存し、形状、内容定義、一時状態は提供側が復元します。
- プラグイン画面から独立した [NyaLauncher-Plugins](https://github.com/TouristH/NyaLauncher-Plugins) レジストリを開き、作者の GitHub Release を正確なサイズと SHA-256 で検証してインストールできます。管理者レビューと配布物のハッシュが完全に一致する版には緑のバッジを表示し、未レビュー版はダウンロード前にリスク確認を求めます。サードパーティ作者はレジストリを Fork し、Pull Request で掲載を申請できます。

> `v0.1.0-gp3` ではパッケージ検出、能力の同意、起動・停止とアンロード、宣言的設定、コンポーネント、トランザクション形式のインスタンス操作、起動ごとの変更を統合しています。
> Forge や Fabric など既存ローダーに依存せず、独自の Mod 規約と Java ローダーを一から定義できます。パッケージ構造、API、例、安全境界は
> [プラグイン開発仕様](NyaLauncher.Plugin.Abstractions/README.md) を参照してください。プラグインはランチャープロセス内で動作し、能力の同意は OS のセキュリティサンドボックスではありません。

## ⚙ メモリ設定

- 設定ページに、512 MiB から端末の物理メモリ総量までを 256 MiB 刻みで選べるグローバル最大メモリスライダーを追加し、`config.json` に保存します。
- 自動調整を有効にするとグローバルスライダーをロックします。各起動直前にその時点の空き物理メモリを取得し、システム用に最低 2 GiB を確保し、ゲームを総メモリの 75% 以下に制限して今回のグローバル上限を決定します。無効にすると保存済みの手動スライダー値へ戻ります。
- インスタンス別の最小・最大メモリもスライダー化し、「個別調整」スイッチで制御します。既定はオフで両スライダーをロックし、グローバル結果をそのまま使用します。有効時の `-Xmx` はインスタンス上限とグローバル手動/自動上限の小さい方です。インスタンス最小値が最終上限を超える場合は `-Xms` も下げます。

## ▦ バージョン管理

- 独立した「バージョン選択と管理」ポリゴンコンポーネントを追加。短押しで管理ページを開き、表示部分の長押しドラッグは維持されます。既存のインスタンスドロップダウンは変更しません。
- Minecraft ルートまたは `versions/<version>` フォルダーを複数追加・切り替えし、選択したフォルダー内のインストール済みインスタンスを選べます。選択は起動ページとクイックドロップダウンに同期します。
- インスタンス ID、Minecraft 基本バージョン、Mod ローダー名と正確なバージョン、種類、リリース日時、Java 要件、メインクラスを個別に表示し、有効なゲームディレクトリから Mod、リソースパック、シェーダー、ゲームセーブを走査します。
- インスタンス選択コンポーネント、クイック選択メニュー、バージョン一覧、詳細見出しにインスタンスアイコンを表示します。バニラ、Fabric、Forge、NeoForge などは対応する代替アイコンを使用し、PCL、MultiMC/Prism、CurseForge、Modrinth App、ATLauncher のModパックは作者または配布サイトのメタデータに含まれるローカル/HTTPS カスタム画像を優先します。すべて縦横比を維持して全体を表示するため、横長・縦長画像も切れず、現在のメニュー項目は別の選択バッジで示します。
- Mod、リソースパック、シェーダー、ワールドを詳細カードで表示します。Mod は Fabric、Quilt、Forge、NeoForge、旧 Forge のメタデータから名前、作者、バージョン、説明、内蔵アイコンを取得します。パックは `pack.mcmeta` と画像、ワールドは `level.dat`、`icon.png`、Minecraft バージョン、作成日時、最終プレイ日時を読み取ります。非標準の作者・バージョン項目がない場合は「未提供」と明示します。
- バニラでは Mod ローダーの導入を案内し、ローダー導入済みで Mod がない場合は0件と表示します。`shaderpacks` フォルダーがある場合だけシェーダータブを表示します。
- 「個別調整」を有効にするとインスタンス別の最小・最大メモリスライダーを操作できます。既定ではロックしてグローバル設定を使用し、実際の最大値も表示します。
- 設定ページのグローバル Java、ウィンドウサイズ、追加 JVM/ゲーム引数は、既定で閉じた「詳細オプション」に格納します。インスタンス側も既定で閉じ、「グローバルに従う」を初期状態で有効にします。従う場合はグローバル値を表示してロックし、無効にした場合だけそのインスタンス固有の詳細起動設定を復元・編集できます。
- バージョン分離をインスタンスごとに明示的に有効・無効化できます。未設定時は PCL の `VersionArgumentIndieV2`/`VersionArgumentIndie`、HMCL、MultiMC/Prism、CurseForge、Modrinth App、ATLauncher のマーカーと `minecraft`/`.minecraft` サブフォルダーを順に確認し、最後に `mods`、`resourcepacks`、`shaderpacks`、`saves`、`config`、`options.txt` などの共通コンテンツ構造へフォールバックします。一覧と詳細には検出元と根拠を表示します。
- 起動作業ディレクトリ、Mod、リソースパック、シェーダー、設定、セーブ、フォルダーショートカットは同じレイアウト解析結果を使用します。`minecraft`/`.minecraft` に内容を置くサードパーティーインスタンスでも外側のバージョンフォルダーを誤読せず、標準 `versions` メタデータを含むラッパーフォルダーも直接追加できます。
- `instance.cfg`、`minecraftinstance.json`、`profile.json`、`instance.json` を持つ外部インスタンスフォルダーも直接追加して内容を閲覧できます。ネイティブのパッチメタデータはまだ NyaLauncher の起動形式へ変換しないため、物理改名と分離切り替えを無効化し、誤った引数で起動せず明確な案内を表示します。
- バージョン名の変更はバージョンフォルダーと同名 JSON/JAR を実際に改名し、JSON の `id` および他バージョンの `inheritsFrom`・`jar` 参照を更新します。不正な名前や既存の移行先は拒否します。
- Minecraft ルート、選択バージョン、Mod フォルダー、セーブフォルダーを素早く開け、Mod またはセーブフォルダーがない場合は作成してから開きます。
- 非同期の詳細結果は現在のフォルダーとバージョンに一致する場合だけ反映し、切り替え・更新中は古い詳細をすぐ消去します。バージョン、Mod、セーブのショートカットはクリック時に現在のレイアウトを再解析し、Windows では Explorer へ明示的に渡して古いパスや誤ったディレクトリ関連付けを避けます。

## 📥 ゲームダウンロード

- ダウンロードページでは Mojang のバージョンマニフェストからバージョンを選び、バージョンメタデータ、ゲームクライアント、依存ライブラリ、リソースインデックス、リソースオブジェクトを現在の Minecraft フォルダーへインストールできます。
- インストールは「バージョンメタデータ取得、ダウンロード計画分析、ゲームクライアント、依存ライブラリ、リソースインデックス、ゲームリソース、最終検証とインストール」の7段階を表示します。
- 進捗画面では現在の段階と詳細、全体進捗、ダウンロード速度、転送バイト数、ファイル数をリアルタイム表示し、実行中タスクをキャンセルできます。
- ファイルは SHA-1 で検証し、検証済みの既存ファイルを再利用します。新規ファイルは一時ファイルへ書き込んでからアトミックに置換し、最大8ファイルを並列ダウンロードします。
- ダウンロード開始時は右下に緑色のフローティング入口を表示します。ダウンロードと起動が同時進行する場合はダウンロードを優先して開き、左側のナビゲーションから起動ログへ切り替えられます。
- ダウンロード進捗を表示中のウィンドウはタスク終了時に自動で閉じます。起動ログへ切り替えたウィンドウはタスク終了では閉じません。起動ログはゲーム起動が一度以上開始された後にのみ、タスク入口から開けます。

## 🎮 オフライン起動

- Minecraft のルートディレクトリや `versions/<version>` の独立インスタンスディレクトリをスキャン可能。
- オンラインのアカウントトークンに依存せず、オフラインユーザー名の検証と決定的な UUID 生成をサポート。
- バージョン継承、モダンおよび旧式の起動引数、OS ルール、classpath の構築に対応。
- ネイティブファイルを安全に展開し、ゲーム終了後に一時ファイルをクリーンアップ。
- バージョン JSON の最低 Java 要件に基づき、Minecraft ランタイム、`NYALAUNCHER_JAVA`、`JAVA_HOME`、または `PATH` から要件に最も近い互換性のある JRE/JDK を選択。明示的な設定があればより高いメジャーバージョンの利用を許可。
- classpath の結合は通常ライブラリ、`natives-*`、`unsafe` といった Maven classifier を区別し、同名の LWJGL 依存が上書きされるのを防止。
- 起動ページにはディレクトリスキャン、バージョン選択、オフラインユーザー名、実行状態と終了コードの表示がある。
- 実行中の起動タスクは右下の円形グローバルタスク入口を共用し、クリックすると今回の Java 標準出力・標準エラーの直近2000行を確認できます。起動・ダウンロードタスク終了後は入口が自動で消えますが、開いた起動ログ画面はゲームプロセス終了後も閉じません。

> オフラインアカウントは正規認証が必要なサーバーには参加できません。起動前に対象バージョン、依存ライブラリ、リソースファイルが揃っていることを確認してください。

v0.1.0-gp3
- 独自の凹多角形・凸多角形の輪郭と個別サイズを宣言できるポリゴンコンポーネント基盤を追加。
- 定義ビルダー、登録、インスタンスファクトリー、ランタイム状態、検証を含む Avalonia 非依存の拡張契約を追加。

- 旧アカウントボタンをポリゴンフレームワークによる小型バー型アカウント選択コンポーネントとして再構築。現在のアカウント名と Microsoft、オフライン、第三者ログイン方式を表示し、メニュー先頭に「アカウントを追加」を固定して保存済みアカウントを一覧表示。
- アカウントコンポーネント、起動ページ、設定ページが同じ現在アカウント順序を共有。追加・切り替えは `config.json` に保存され、旧 `account` コンポーネント ID は新 ID へ移行。
- 小型バー型の「ゲームインスタンス選択」コンポーネントを追加。現在のインスタンス名を表示し、右側のドロップダウンに選択中の Minecraft フォルダー内の全インストール済みバージョンを一覧表示します。コンポーネントと起動ページは選択状態を共有・保存し、ディレクトリ走査はバックグラウンドで実行します。
- 独立した「バージョン選択と管理」コンポーネントとページを追加。複数のバージョンフォルダー、バージョン・Mod・リソースパック・利用可能なシェーダーの詳細、実際に適用される起動設定、フォルダーショートカットに対応。バージョン名変更はフォルダー、JSON、JAR を直接改名し、継承参照も修正します。
- アクティブなタスクがないのに右下のタスク入口が残る問題を修正。完了、失敗、キャンセル、ゲーム終了後は入口を隠し、既に開いた起動ログは維持します。
- インスタンスごとの明示的なバージョン分離設定を追加し、インスタンス一覧の重複したバージョン表示を修正。分離時は作業ディレクトリ、Mod、リソースパック、シェーダー、設定、セーブを `versions/<current-version>` に統一し、一覧には分離または共有ディレクトリを表示します。
- Minecraft ルートから入った場合にサードパーティランチャーの分離インスタンスを認識できない問題を修正。追跡可能な共通レイアウト解析を追加し、PCL、HMCL、MultiMC/Prism、CurseForge、Modrinth App、ATLauncher の代表的なマーカーと入れ子コンテンツを認識してから実際の内容構造へフォールバックします。詳細には検出元、セーブ一覧、セーブフォルダーを開く入口も表示します。
- 既知のメタデータマーカーを持つサードパーティーインスタンスフォルダーを直接追加し、独立コンテンツを読み取り専用で管理できるようにしました。ネイティブパッチ変換が完成するまでは直接起動と物理改名を明示的に停止します。
- バージョン詳細とフォルダーショートカットが前のインスタンスパスを保持する問題を修正。詳細完了時に現在の選択を検証し、更新時は古いデータを消去し、各入口はクリック時に現在のインスタンスを再解析して Windows では Explorer で開きます。

- バージョン詳細に Minecraft 基本バージョンと Mod ローダーの正確なバージョンを追加。設定ページとインスタンスページの Java、ウィンドウサイズ、JVM、ゲーム引数を既定で閉じた「詳細オプション」へ統合しました。グローバル値を保存し、インスタンスは既定で追従・ロックされ、追従を解除した場合のみ固有値を編集して起動時に適用します。
- インスタンスとコンテンツ管理にアイコンと詳細メタデータを追加。インスタンスはローダー別の代替アイコンとサードパーティーModパックのカスタム画像に対応し、Mod、リソースパック、シェーダー、ワールドには名前、作者、バージョン/日時、説明、利用可能なアイコンを表示します。JAR/ZIP と `level.dat` の走査はバックグラウンドで行い、サイズ制限を確認した圧縮内画像だけをコンテンツアイコンキャッシュへ展開します。

- ポリゴンフレームワークで「ゲーム起動」コンポーネントを再構築。非インタラクティブ部分を短押しすると現在のアカウントで選択中のインスタンスを直接起動し、準備中・実行中・失敗・終了状態をリアルタイムに反映します。起動ページと単一の起動パイプラインを共有し、重複起動を防止します。
